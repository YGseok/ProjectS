너는 이 Godot 4.x 게임 프로젝트(ProjectS)를 반복적으로 다듬는 개발 루프의 한 이터레이션이다.
너는 이전 이터레이션을 기억하지 못한다. 모든 문맥은 아래 파일들에서만 얻는다.

## 0. 반드시 이 순서로 먼저 읽어라

1. `docs/DESIGN.md` — 무엇을 만드는가, 완료 기준이 무엇인가
2. `docs/STATUS.md` — 지금 위치, 다음 할 일 큐, 완료 기록 (인수인계서)
3. `docs/feedback/INBOX.md` — 사람의 직접 지시/피드백. **큐의 다른 어떤 항목보다
   우선한다.** 대기 중 항목이 있으면 그것부터 처리하라.

## 1. 이번 이터레이션에서 할 일

- INBOX.md에 처리 대기 항목이 있으면 그것을 최우선으로 처리한다.
- 없다면 STATUS.md의 "다음 할 일 큐"에서 맨 위 항목을 하나 처리한다
  (한 이터레이션 = 한 개의 작지만 완결된 작업. 너무 크게 벌이지 마라).
- 코드/씬을 수정했다면 **반드시** `qa/run_qa.sh` 로 시각 QA를 실행해서
  네가 만든 화면을 직접 확인해라. 예:
  `GAME_START=<씬키> ./qa/run_qa.sh`
- 캡처된 PNG를 열어서(이미지 읽기 도구로) 실제로 확인하라. 파일이
  생성되었다는 사실만으로 "완료"라고 판단하지 마라 — 반드시 내용을 봐라.
- 문제가 보이면 같은 이터레이션 안에서 즉시 고치고 다시 캡처해서 재확인하라.

## 2. 완료 기준

`docs/DESIGN.md` §6 을 따른다:
- 자동 기준: 지정 씬이 크래시 없이 로드되고, 지정 프레임에서 PNG가 정상 저장됨
- 사람 기준: 스크린샷을 실제로 보고 드는 개별 피드백이 없어야 함
  (있다면 INBOX.md에 남겨질 것이므로, 지금 이터레이션에서는 자동 기준까지만
  확실히 만족시키고 넘어가도 된다)

## 3. 마치기 전에 반드시 할 일 — STATUS.md 갱신

`docs/STATUS.md`를 **다음 세션에게 남기는 인수인계서**라고 생각하고 갱신하라:

- "지금 위치": 지금 막 무엇을 했는지, 프로젝트가 지금 어떤 상태인지 다시 서술
- "다음 할 일 큐": 다음 세션이 이어서 할 일을 우선순위대로 다시 정리
  (이번에 처리한 항목은 빼고, 새로 발견한 할 일이 있으면 추가)
- "완료 기록": 이번 이터레이션에서 한 일을 한두 줄로 맨 위에 추가
- STATUS.md 안의 "이터레이션 종료 시 체크리스트"를 실제로 확인하고 반영하라

INBOX.md에서 처리한 항목이 있다면 `[처리됨]` 표시를 남기고
"처리된 항목" 섹션으로 옮겨라 (내용은 지우지 말고 그대로 옮길 것).

## 4. 하지 말아야 할 것

- 이 프롬프트나 DESIGN.md의 방향과 다른 임의의 큰 설계 변경을 혼자 결정하지 마라 —
  불확실하면 STATUS.md에 "확인 필요" 항목으로 남기고 다음 사람 검토를 기다려라.
- QA 캡처 없이 "될 것 같다"고 넘어가지 마라.
- STATUS.md 갱신을 생략하고 끝내지 마라 — 이게 없으면 다음 세션은 아무것도 모른다.
